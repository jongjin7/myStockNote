# 커밋 메시지 컨벤션 (Commit Message Convention)

이 프로젝트는 [Conventional Commits](https://www.conventionalcommits.org/) 규칙을 따릅니다.

## 기본 형식
```
<type>: <description>

[body] (선택 사항)
```

## Type 종류
| Type | 설명 | 예시 |
|------|------|------|
| **feat** | 새로운 기능 추가 | `feat: 사용자 로그인 기능 추가` |
| **fix** | 버그 수정 | `fix: 모달 닫기 버튼 오류 수정` |
| **docs** | 문서 수정 | `docs: README.md 설치 가이드 업데이트` |
| **style** | 코드 포맷팅, 세미콜론 누락 등 (로직 변경 없음) | `style: 들여쓰기 수정` |
| **refactor** | 코드 리팩토링 (기능 변경 없음) | `refactor: StockCard 컴포넌트 분리` |
| **test** | 테스트 코드 추가, 리팩토링 | `test: 로그인 API 테스트 케이스 추가` |
| **chore** | 빌드 태스크, 패키지 매니저 설정 등 | `chore: 패키지 의존성 버전 업데이트` |

## 작성 규칙
1. **Description(제목)**
   - **한글**로 작성합니다.
   - 명령문으로 시작하거나 명사형으로 끝맺습니다. (예: `~추가`, `~수정`, `~삭제`)
   - 마침표(.)는 사용하지 않습니다.

2. **Body(본문)** (선택)
   - 제목만으로 설명이 부족할 때 상세 내용을 적습니다.
   - '무엇을', '왜' 변경했는지 위주로 작성합니다.

## 예시
```
feat: 포트폴리오 요약 카드 UI 구현

- 총 평가액 및 수익률 표시 영역 추가
- 반응형 디자인 적용
```
